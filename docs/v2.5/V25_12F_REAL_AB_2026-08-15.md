## Site Boundary diagnostic correction

The first acceptance report contained:

```text
current_lane_site_boundary_conflicts   17
candidate_lane_site_boundary_conflicts 17
```

That number was produced by counting the substring `SITE_BOUNDARY_CONFLICT` in the lane reason.

The original lane implementation added that token whenever any candidate pose anywhere along an aisle was rejected by the boundary. For agricultural aisles whose structural centerlines extend close to headland/perimeter endpoints, that does not mean the whole aisle is blocked by Site Boundary.

The diagnostic contract has therefore been corrected without weakening the boundary gate.

New per-lane metrics:

```text
site_boundary_rejected_pose_count
site_boundary_limited_sample_count
grid_rejected_pose_count
```

New acceptance summaries:

```text
site_boundary_rejected_pose_aisles
site_boundary_limited_aisles
site_boundary_fully_blocked_aisles
```

Definitions:

```text
rejected pose
= a sampled candidate footprint touches/crosses Site Boundary

limited sample
= at that longitudinal station at least one candidate is Navigation-Grid FREE
  when ignoring Site Boundary, but no candidate survives the Site Boundary gate

fully blocked aisle
= NO_VEHICLE_SAFE_LANE and every sampled station is boundary-limited
```

This separates expected endpoint/perimeter rejection from a boundary that actually destroys the entire lane.

The corrected metrics require one new operator-machine acceptance rerun before drawing conclusions from Site Boundary counts.
