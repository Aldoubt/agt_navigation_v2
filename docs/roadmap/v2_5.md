# AGT Navigation V2.5 Roadmap

The current development line is:

```text
AGT Navigation V2.5
        ↓
P0 First BT Mission
        ↓
P1 Robust Localization / Local Mapping
        ↓
P2 Long-term Agricultural Navigation Research
```

## DONE

Existing stable foundations include the FAST-LIVO2 mapping adapter, registered
cloud and PCD persistence, ICP/NDT relocalization, Nav2 waypoint Action,
safety/chassis boundaries, semantic/keepout offline products, structured
system health/readiness, and the project `agt_mission_manager` business Action/FSM
boundary. “DONE” means implemented or supported by stated offline or bag evidence;
it is not a blanket vehicle acceptance claim.

## P0 — First BT Mission

- URDF collision-based self-filter geometry while preserving the existing
  CustomMsg input/output boundary. V25-02 implementation exists; raw/profile/URDF
  bag comparison and vehicle false-removal/missed-removal validation remain before DONE.
- Sensor health evidence. V25-03 implementation exists (`agt_sensor_monitor`),
  while bag/vehicle validation and measured deployment tuning remain pending.
- Semantic waypoint mode and schema 1.1 waypoint extension.
- Add a BehaviorTree.CPP + Groot2 execution engine behind the existing
  `agt_mission_manager` boundary. Do not create a second project Mission state owner.
- First finite BT mission must call project Actions and structured readiness contracts.

## P1 — Robustness

Rolling local mapping, raycast/log-odds timeout behavior, ground plane/factor,
GNSS and wheel factors, and a GTSAM/iSAM2 backend.

## P2 — Research

STD/Scan Context loop closure, long-term multi-layer maps, cross-growth
relocalization, and seasonal/structural agricultural navigation research.

## OPTIONAL

Operator and visualization enhancements that do not become business-state or
motion owners.

## Scope boundary

Semantic coverage, dynamic semantic perception, realtime traversability, and
long-term map algorithms remain separately gated capabilities. This roadmap does
not claim them as executable or vehicle-validated. P0 implementation status must
still distinguish source code present from bag/vehicle acceptance evidence.
