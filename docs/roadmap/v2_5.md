# AGT Navigation V2.5 Roadmap

The current delivery line is:

```text
P0   First BT Mission                         PASS software integration; vehicle validation separate
V25-08 Architecture & Semantics Baseline      IMPLEMENTED; runtime interfaces unchanged
V25-09 Robust Route Navigation Core
V25-10 Sparse Global Correction / Anchor Recovery
V25-11 Local Environment Mapping
V25-12 Optional ESDF / Advanced Local Planning
```

GNSS / Wheel / GTSAM remain on the P1 state-estimation track. STD / Scan Context and
seasonal maps remain on the P2 research track.

## DONE

Existing stable foundations include the FAST-LIVO2 mapping adapter, registered
cloud and PCD persistence, ICP/NDT relocalization, Nav2 waypoint Action,
safety/chassis boundaries, semantic/keepout offline products, structured
system health/readiness, and the project `agt_mission_manager` business Action/FSM
boundary. “DONE” means implemented or supported by stated offline or bag evidence;
it is not a blanket vehicle acceptance claim.

## V25-08 — Architecture & Semantics Baseline

IMPLEMENTED as a documentation/interface-contract baseline without changing runtime
ROS messages, services, actions, or launch behavior.

The frozen semantics are:

- Navigation Capability is the project boundary; Nav2 is an internal backend rather than the definition of Navigation.
- Navigation modes are `MAP`, `ROUTE`, and `LOCAL`; only the MAP-oriented baseline is currently implemented.
- Global Navigation Map, Localization Prior, Semantic Map, and Local Environment Map have separate lifetime/ownership semantics.
- `/agt/map/local_occupancy` is reserved as an `odom`-frame transient rolling product; ESDF is optional and derived.
- `SemanticWaypoint != WaypointTask != Route != Runtime Path`.
- `odom -> base_footprint` has one FAST-LIVO2-adapter owner; authoritative `map -> odom` belongs to the localization subsystem with exactly one selected runtime TF publisher.
- Current baseline TF publication remains the `agt_relocalization` node with `publish_tf=true`; future fusion ownership must replace, not duplicate, that publisher.
- Current `EvaluateTaskReadiness.srv` remains unchanged; future mode-aware readiness is reserved for separate versioned interface work.

## V25-09 — Robust Route Navigation Core

Future work: Route resolution, route segments, odometry-frame runtime paths and
controller/path follower integration. The first implementation should continue to use
project capability boundaries and should not add a new Mission schema merely to select
an internal backend.

## V25-10 — Sparse Global Correction / Anchor Recovery

Future work: anchor/confidence-triggered global correction. NDT/ICP, GTSAM, GNSS and
place-recognition components may provide correction evidence, but the selected
localization owner remains the sole `map -> odom` publisher.

## V25-11 — Local Environment Mapping

Future work: ground/obstacle separation, rolling local occupancy, raycast/log-odds and
observation timeout/decay. The canonical local product is reserved in `odom` so sparse
global corrections do not force the local obstacle representation to become global-map truth.

## V25-12 — Optional ESDF / Advanced Local Planning

ESDF is an optional derived representation after local occupancy; it is not a P1
default prerequisite.

## P1 / P2 tracks

GNSS, wheel factors and GTSAM/iSAM2 remain P1 state-estimation work. Ground factors are
also a P1 state-estimation constraint and are not part of the local-map representation
itself. STD/Scan Context, loop closure, long-term multi-layer maps and seasonal/structural
agricultural navigation remain P2 research.

## OPTIONAL

Operator and visualization enhancements that do not become business-state or
motion owners.

## Scope boundary

Semantic coverage, dynamic semantic perception, realtime traversability, and
long-term map algorithms remain separately gated capabilities. This roadmap does
not claim them as executable or vehicle-validated. Architecture documents may reserve
future capability names, but reserved names do not imply runtime publishers, ROS
interfaces, launch wiring, or vehicle acceptance.
